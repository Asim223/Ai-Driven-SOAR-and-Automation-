## Before presenting

Review the report and all recorded AI outputs. Keep the successful AI evidence available in case Ollama is slow. Use one server process. Each new run creates fresh browser incident IDs; locate records by dataset, run and entity. Do not infer approval latency from an automated request. The action plan can still say awaiting_approval after a separate decision has been recorded; use the audit record as evidence.

## Questions to prepare for

- Why is the administrator score still 91 after removing malware_signal? The probability drops, but the weighted and rounded score is unchanged.
- Why does quarantine retain malware_signal? It is a threat-detection feature, not proof of execution; prevention is recorded separately.
- What does idempotency cover? Duplicate decision requests for the same run, incident, entities, action and playbook version in the single-process browser app.
- Can a hash chain prevent all tampering? No. Complete rewriting needs an external trusted checkpoint to detect reliably.
- What did AI get wrong? Duplicate actions, missing a recorded destination, and a benign-closure recommendation inconsistent with its own narrative.
- Is capstone performance 100 percent? No labels are available; only the small training set has measured metrics.
